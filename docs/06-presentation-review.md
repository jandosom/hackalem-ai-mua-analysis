# Презентация проекта для Demo Day

Сильная презентация ОргДифф должна показывать конкретную задачу специалиста, работающий сценарий и проверяемую находку. Технически грамотный конвейер полезно объяснять через результат: какая обязанность изменилась, на каких пунктах основан вывод и какое решение может принять сотрудник.

Разбор относится к презентационным материалам и заявлениям проекта. Он не устанавливает качество фактической защиты 16 октября: видеозаписи выступлений и финальные ответы команд здесь не анализировались.

## Какие заявления требуют исправления

| Формулировка | Почему она вводит в заблуждение | Корректная замена |
|---|---|---|
| 100 процентов смыслового аудита или точности | Цитаты проверяются программно, но смысловая интерпретация может быть ошибочной | Каждая показанная находка сопровождается проверяемым пунктом; вывод проверяет специалист |
| Полный анализ за две минуты | Быстрый mock воспроизводит сохранённые ответы; служебный live-прогон занял 824 секунды | Отдельно сообщать время mock и измеренное время нового live-прогона с описанием условий |
| Ручная работа занимает от трёх до пяти дней | Сопоставимого измеренного ручного сценария нет | Описать конкретные операции, которые система автоматизирует, без количественной экономии |
| Нет ложных срабатываний | Независимая размеченная выборка и precision/recall не представлены | Показать найденные случаи и ограничения их проверки |
| Ноль конфликтов означает отсутствие конфликтов | Система не нашла их на конкретном комплекте; это не доказательство их полного отсутствия | На контрольном комплекте конфликтов не найдено |
| Заключение полностью готово для регулятора | Нет полноценной правовой проверки и внешнего согласования | Аналитическое заключение для проверки ответственным специалистом |
| Шесть изменений подразделений | В шести записях три подразделения сохранены | Шесть записей сопоставления: три сохранено, два преобразовано, одно создано |
| Число замечаний показывает точность | Большее число находок может включать больше ошибок | Точность оценивается по экспертному эталону, а не числу карточек |

Контрольные данные, происхождение mock и ограничения зафиксированы в README и записи live-прогона ([https://github.com/BAITC-Hacks/hack-ec659486-mua/blob/9eb689e65ef5c551667c53787b96825ef9cc80d1/README.md](https://github.com/BAITC-Hacks/hack-ec659486-mua/blob/9eb689e65ef5c551667c53787b96825ef9cc80d1/README.md)), ([https://github.com/BAITC-Hacks/hack-ec659486-mua/blob/9eb689e65ef5c551667c53787b96825ef9cc80d1/status/agents/S15.md](https://github.com/BAITC-Hacks/hack-ec659486-mua/blob/9eb689e65ef5c551667c53787b96825ef9cc80d1/status/agents/S15.md)).

## Как показывать доказательство

Для одной находки достаточно последовательности: исходная обязанность → ближайший пункт новой редакции → объяснение смысловой разницы → источники → действие специалиста. Такой пример показывает назначение системы лучше списка технологий.

Для контрольного комплекта можно разбирать редакцию 8, пункт 5.3.4.б, где закреплён контроль сроков выполнения графика проверки проектной командой, и ближайший пункт редакции 9, 5.3.4.в. Формирование графика и постановка задач не тождественны отдельной обязанности контролировать сроки. При этом окончательное заключение требует проверки полного контекста и возможного покрытия в других пунктах.

Второй пример — доведение результатов консультационных услуг до руководителей общества, редакция 8, пункт 5.7.2. Эти случаи приведены как результаты конкретного контрольного сценария, а не доказательство универсальной точности агента.

При показе дубля из пунктов 5.4.1 и 5.5.1 новой редакции важно объяснить область ответственности. Похожая обязанность руководителей распределять работу между собственными сотрудниками сама по себе может быть нормальной. Наличие похожих слов и проверенной цитаты не завершает предметную проверку.

## Что можно перенять у призёров

Singularity показывает переходы функций на схеме и предлагает получателей утраченных обязанностей. Optimus связывает обзор, рекомендации, историю и документ для передачи результата. Kontur облегчает проверку цитат и фиксацию решения специалиста. Для следующей демонстрации MUA полезно показать, как специалист завершает работу с найденной проблемой, а не только как агент её обнаруживает.

Эти продуктовые различия не подтверждают, что именно презентация стала причиной распределения наград. Опубликованные баллы и правила финального решения рассмотрены отдельно в [разборе оценок](03-jury-scores-and-comments.md).
